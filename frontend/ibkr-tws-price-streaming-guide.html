In the TWS API, there are several streaming methods, but for your pair-level take-profit/max-loss engine, reqMktData() is the primary method you want.

1. reqMktData() — recommended for your risk engine

This provides continuous Level 1 market data:

  • Bid
  • Ask
  • Last
  • Bid size
  • Ask size
  • Last size
  • Close
  • Optional mark price and other generic ticks

It is a subscription, not a one-time request:

self.reqMktData(
    reqId=1001,
    contract=contract,
    genericTickList="221",
    snapshot=False,
    regulatorySnapshot=False,
    mktDataOptions=[]
)

The important parameter is:

snapshot=False

That keeps the subscription open until you call:

self.cancelMktData(1001)

IBKR publishes updates through callbacks:

from ibapi.ticktype import TickTypeEnum

def tickPrice(self, reqId, tickType, price, attrib):
    field = TickTypeEnum.toStr(tickType)

    print(
        "request:", reqId,
        "field:", field,
        "price:", price
    )

def tickSize(self, reqId, tickType, size):
    field = TickTypeEnum.toStr(tickType)

    print(
        "request:", reqId,
        "field:", field,
        "size:", size
    )

reqMktData() is aggregated Level 1 data delivered several times per second, not necessarily every individual exchange tick. It is normally sufficient for monitoring 15 pairs. IBKR streaming market-data documentation.

ETF example

IBKR classifies exchange-traded stocks and ETFs as STK:

from ibapi.contract import Contract

spy = Contract()
spy.symbol = "SPY"
spy.secType = "STK"
spy.exchange = "SMART"
spy.primaryExchange = "ARCA"
spy.currency = "USD"

self.reqMktData(
    1001,
    spy,
    "221",
    False,
    False,
    []
)

If you already resolved the contract, using its conId is safer:

spy = Contract()
spy.conId = spy_underlying_conid
spy.secType = "STK"
spy.exchange = "SMART"
spy.currency = "USD"

Generic tick 221 requests the IBKR mark price used in TWS P&L calculations. Bid, ask, last and their sizes are part of the normal default tick stream.

2. Stock/ETF CFD market data requires the underlying

This is the most important CFD peculiarity:

IBKR generally does not provide a separate market-data stream for stock or ETF CFDs. TWS displays the market data of the CFD’s underlying stock or ETF.

Therefore:

Instrument traded → SPY CFD
Instrument priced → SPY underlying ETF, secType=STK

Your instrument record should contain both:

trade_conid       = SPY CFD conId
market_data_conid = SPY ETF/STK conId

Use trade_conid in placeOrder() and market_data_conid in reqMktData().

If you request data on the CFD contract, TWS API can invoke:

def rerouteMktDataReq(self, reqId, conId, exchange):
    print(
        "CFD request:", reqId,
        "underlying conId:", conId,
        "underlying exchange:", exchange
    )

The callback identifies the underlying instrument that has market data. IBKR CFD market-data rerouting.

You can then subscribe explicitly:

def rerouteMktDataReq(self, reqId, conId, exchange):
    underlying = Contract()
    underlying.conId = conId
    underlying.secType = "STK"
    underlying.exchange = exchange
    underlying.currency = "USD"

    underlying_req_id = self.allocate_request_id()

    self.reqMktData(
        underlying_req_id,
        underlying,
        "221",
        False,
        False,
        []
    )

In production, it is better to discover and cache the underlying conId when qualifying the CFD, rather than waiting for rerouting while a position is live.

Index CFDs are different and can generally be queried directly as CFDs.

3. reqTickByTickData() — individual ticks

If you need higher-granularity data than reqMktData():

self.reqTickByTickData(
    reqId=2001,
    contract=spy,
    tickType="BidAsk",
    numberOfTicks=0,
    ignoreSize=True
)

Available stream types include:

Last
AllLast
BidAsk
MidPoint

Callbacks include:

def tickByTickBidAsk(
    self,
    reqId,
    time,
    bidPrice,
    askPrice,
    bidSize,
    askSize,
    tickAttribBidAsk,
):
    ...

and:

def tickByTickAllLast(
    self,
    reqId,
    tickType,
    time,
    price,
    size,
    tickAttribLast,
    exchange,
    specialConditions,
):
    ...

Cancel with:

self.cancelTickByTickData(2001)

I would not start with tick-by-tick subscriptions for all 30 legs. They have tighter subscription limitations and generate considerably more events. Level 1 reqMktData() is usually enough for pair exits.

4. reqRealTimeBars() — five-second OHLC bars

This streams five-second bars:

self.reqRealTimeBars(
    reqId=3001,
    contract=spy,
    barSize=5,
    whatToShow="MIDPOINT",
    useRTH=False,
    realTimeBarsOptions=[]
)

Callback:

def realtimeBar(
    self,
    reqId,
    time,
    open_,
    high,
    low,
    close,
    volume,
    wap,
    count,
):
    ...

Cancel with:

self.cancelRealTimeBars(3001)

This is useful for:

  • monitoring;
  • charts;
  • volatility calculations;
  • five-second signal logic.

It is not ideal for stop-loss processing because a five-second bar can arrive too late relative to a fast price move. IBKR currently provides only five-second bars through this method. IBKR TWS API reference.

5. reqMktDepth() — Level 2 order book

If you need multiple price levels:

self.reqMktDepth(
    tickerId=4001,
    contract=spy,
    numRows=5,
    isSmartDepth=True,
    mktDepthOptions=[]
)

Callbacks:

def updateMktDepth(...):
    ...

def updateMktDepthL2(...):
    ...

Cancel with:

self.cancelMktDepth(4001, True)

This is unnecessary for basic pair P&L. It consumes separate depth entitlements and has tighter limits. Use it only if your execution logic explicitly models order-book liquidity. IBKR market-depth documentation.

6. reqPnLSingle() — streams P&L, not raw prices

For an open position:

self.reqPnLSingle(
    reqId=5001,
    account="U1234567",
    modelCode="",
    conId=spy_cfd_conid
)

Callback:

def pnlSingle(
    self,
    reqId,
    pos,
    dailyPnL,
    unrealizedPnL,
    realizedPnL,
    value,
):
    ...

This gives:

  • Current position
  • Daily P&L
  • Unrealized P&L
  • Realized P&L
  • Market value

It updates approximately once per second, but it does not provide bid and ask prices. It is valuable as an independent broker-side P&L check.

Remember that it reports the consolidated account position for that conId, not the portion allocated to a particular pair.

7. Position methods are not price streams

These methods help discover positions but should not drive real-time exits:

reqPositions()

self.reqPositions()

Callback:

def position(self, account, contract, position, avgCost):
    ...

It gives quantity and average cost, but no live price.

reqAccountUpdates()

self.reqAccountUpdates(True, "U1234567")

Its updatePortfolio() callback includes marketPrice, market value and P&L, but IBKR documents that unchanged positions may update only at a fixed interval of roughly three minutes. That is too slow for a max-loss trigger.

Recommended combination for your OEMS

For every open pair:

CFD conId         → order placement and reqPnLSingle()
Underlying conId  → reqMktData()

Subscribe to:

reqMktData(underlying_conid)
reqPnLSingle(cfd_conid)

Then maintain:

Pair P&L from bid/ask and your execution ledger
        versus
IBKR P&L from pnlSingle()

Use the market-data calculation for fast triggers and IBKR’s P&L as a reconciliation/control stream.

For calculating liquidation P&L:

Long leg  → value at bid
Short leg → value at ask

For example:

def leg_unrealized_pnl(signed_qty, entry_price, bid, ask, multiplier=1):
    exit_mark = bid if signed_qty > 0 else ask
    return signed_qty * (exit_mark - entry_price) * multiplier

Market-data permission warning

CFD trading permission does not automatically include market-data permission for the underlying US ETF or stock. You need the relevant US equity market-data subscription in Client Portal.

Also confirm the returned data type:

def marketDataType(self, reqId, marketDataType):
    # 1 live, 2 frozen, 3 delayed, 4 delayed-frozen
    print(reqId, marketDataType)

Do not allow delayed data—type 3 or 4—to drive an automated max-loss system. For your 15 pairs, approximately 30 underlying Level 1 subscriptions through reqMktData() are the appropriate starting point.
